# ADR: isolated developer API v1 — synthetic first slice

Independent `/api/developer/v1`, not legacy API compatibility. Type 203 maps only to synthetic `message.send_text`, one target / one child initially; accepted is not execution success. All other types/routes return 501.

Admin creates tenant-local app, scopes and active device bindings. App bearer token is random, once-only response, SHA256-only storage; rotate invalidates prior token. App actor is explicit `actor_type=app,app_id`; legacy commands.actor references creating admin as provenance ONLY. User command guard remains active operator, app guard independently checks app active/scopes/device binding at submit, dispatch and execution events. Owner gains no privileges.

Result changes enqueue immutable callback events within the same SQLite transaction. Callback delivery is at least once, stable event ID; HMAC SHA256 over `eventId.timestamp.rawBody`; receivers must verify signature/time and dedupe event ID. HTTP 2xx acknowledges delivery, never effect. Bounded retry then deadletter visible to app. Default networking disabled. Only explicitly configured exact synthetic `http://127.0.0.1:port` receiver permitted for local tests; no DNS, arbitrary URLs, redirects or production private network requests. Production HTTPS/key provider NOT_IMPLEMENTED; ephemeral callback keys vanish at restart and old deliveries deadletter rather than silently rotate. App API tokens are not callback keys.

No real WeCom execution. Existing unknown-side-effect and asynchronous revocation race limitations remain. No automatic command replay. Idempotency is tenant+app+key with canonical request hash; changed input conflicts. IDs batch/message/child are separate even with one child. Callback metadata excludes text/raw command payload. No retention GC implemented; production storage encryption/key custody pending.

## Actual routes
- Browser admin + CSRF: POST/GET `/applications`; POST `/applications/:id/rotate`, `/revoke`; PUT `/applications/:id/bindings {deviceIds}`; POST `/applications/:id/callback {url}`. Tokens expire in one hour; rotation returns new once-only token. Expiry blocks new API use AND queued dispatch. Each command snapshots app credential epoch; rotation increments epoch, so old-token queued commands cannot dispatch. Expiry/rotation/revocation/unbinding also request stop at the existing execution safe-point guard; already applied effects are not undone.
- App Bearer: GET `/devices` (`devices:read`), POST `/messages` (`commands:write`, Idempotency-Key) body `{type:203,deviceId,targetId:"synthetic_demo",text,expiresInSeconds:30..300}`; GET `/messages/:messageId` (`results:read`); GET `/deliveries` (`callbacks:read`). Body does not control tenant/app. Only known fields allowed.
- Callback receiver headers: `x-worktool-event-id`, `x-worktool-timestamp` (Unix milliseconds), `x-worktool-signature` (hex). Secret response is hex representing HMAC key bytes; receivers must decode hex. Verify ±30 seconds, exact raw bytes; persist event ID dedupe. Same event ID/body across retries, fresh signed timestamp. Retry waits 1/2/4 seconds, fourth unsuccessful delivery deadletters; no automatic manual replay endpoint in this slice.
- API keys, callback secrets never logged; callback DB contains minimal status identifiers, no message text or raw device payload. Default callback configuration rejects with 501; arbitrary hostname, localhost alias, private network, changed port and redirects are not supported. Only literal configured test loopback destination reaches HTTP implementation.
- Revocation cannot retract an already transmitted callback or irreversible device effect. Queue authorization checks are strong; in-flight network windows remain explicitly bounded by actual evidence, not fictional exactly-once semantics.

## Approved reliability amendment (same isolated slice)
Three explicit unknown→unstarted-terminal reconcile edges repair lost pre-effect receipts on reconnect. Guard consults historical command_events, not only current state. A prior begin/running or effect/terminal fact blocks downgrade to unstarted. Authenticated same device/attempt, journal refs and immutable result+ACK transactions retain existing trust boundaries; no command replay and no ACK-as-permit introduced.
